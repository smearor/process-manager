Expand description

Manages multiple child processes.

Uses DashMap for concurrent access (matching swipe-launcher’s pattern). Supports both ProcessId-based and label-based operations.

pub fn with_reaper( poll_interval: Duration, exit_sender: Sender<ProcessExitEvent>, ) -> Result<Self, ProcessManagerError>

Create a new ProcessManager with a reaper thread.

The reaper uses non-blocking try_wait() on all tracked processes every poll_interval and emits ProcessExitEvents to the provided channel. This prevents zombies without blocking a thread per process.

Source

pub fn start( &self, label: &str, config: &ProcessConfig, ) -> Result<ProcessId, ProcessManagerError>

Spawn a new child process with the given label and configuration.

Returns the assigned ProcessId. If config.forked is true, setsid() is applied via pre_exec to detach from the controlling terminal. The process is still tracked in the DashMap (with its Child handle) for stop/reaper operations.

Source

pub fn get(&self, id: ProcessId) -> Option<Ref<'_, ProcessId, Process>>

Get a managed process by ID.

Returns a dashmap::mapref::one::Ref guard. The process is accessible within the guard’s lifetime.

Source

pub fn get_by_label(&self, label: &str) -> Vec<(ProcessId, ProcessInfo)>

Get all processes with a given label.

Returns a list of (ProcessId, ProcessInfo) snapshots. The processes remain in the manager. Snapshots contain metadata only — no Child handle. Use stop() / stop_label() for process control.

pub fn stop(&self, id: ProcessId) -> Result<(), ProcessManagerError>

Stop (kill) a specific process by ID.

Sends the configured kill signal via nix::sys::signal::kill, waits the grace period, then escalates to SIGKILL if still alive. Removes the process from the manager.
